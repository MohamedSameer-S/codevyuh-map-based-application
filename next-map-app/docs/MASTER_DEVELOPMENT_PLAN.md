# CodeVyuh: Master Technical Development Plan (v2.0)

## 1. Architectural Paradigm: The Infinite Canvas
The CodeVyuh ecosystem requires an architecture that can support $O(N)$ regions while maintaining 60fps DOM rendering. We are abandoning static coordinate generation in favor of a **Dynamic QuadTree Boundary System** combined with **SVG DOM Recycling**.

### 1.1 Context & Control Isolation (The C&C Protocol)
To ensure seamless scaling, the project strictly segregates state from rendering via the **Context & Control** directories:
- **`context/`**: Defines the immutable laws of the ecosystem. Contains deep technical specifications on the SVG rendering pipeline, matrix math definitions (`scaleY(0.6)` bounds), and procedural generation constraints.
- **`control/`**: The active orchestration layer. Houses the `GlobalStore` (state machine), `EventBus` (decoupled pub/sub communication), and mathematical controllers (e.g., `CameraPhysics`).

## 2. Procedural Ecosystem Engineering
The world must terraform itself dynamically.

### 2.1 Topographical Generation (Perlin-Bounded Coastlines)
- **Algorithm**: Instead of basic bezier curves, coastlines will be generated using a 1D Perlin noise array mapped to a radial projection around the calculated bounding box of all regions.
- **Elevation Matrices**: The 3 elevation tiers (Lowlands, Plains, Highlands) will be generated by applying a morphological erosion algorithm to the base radial projection, ensuring highlands only spawn deep inland.

### 2.2 Algorithmic Pathfinding (Rivers & Roads)
- **Algorithm**: Implement an **A* (A-Star) Pathfinding** heuristic operating on a hidden virtual grid (100x100 node resolution). 
- **River Logic**: Rivers originate at `Highland` nodes and pathfind to the nearest `Ocean` node, assigning infinite cost to `Region Hitboxes` to guarantee they never clip through learning tracks.
- **Road Logic**: Dirt roads pathfind between Region centers using a Minimum Spanning Tree (MST) to ensure all tracks are connected efficiently.

### 2.3 Scatter Ecology (Poisson Disk Sampling)
- **Algorithm**: Replace random `Math.random()` scattering with **Poisson Disk Sampling**. This guarantees even, organic distribution of forests, rocks, and ruins without unnatural clustering or overlap.
- **Biome Masking**: The sampling algorithm checks the `BiomeConfig` of the nearest region. If `jungle`, it instantiates dense `<polygon>` palm clusters; if `wasteland`, it instantiates sparse corrupted crystals.

## 3. Advanced Rendering Pipeline & Optimization
Rendering thousands of procedural SVG nodes will bottleneck the main thread if not optimized.

### 3.1 SVG ViewBox Culling (DOM Recycling)
- **Implementation**: Instead of rendering a 50,000 x 50,000 SVG, we implement a spatial hash. SVG elements (trees, mountains) outside the current `CameraController` viewport are dynamically detached from the DOM and stored in memory. As the user pans, nodes are recycled into the viewable area.

### 3.2 Hardware-Accelerated 2.5D Math
- **Implementation**: We strictly enforce `transform: translate3d(x, y, 0)` on the global `worldGroup` to force GPU compositing.
- **Isometric Constraint**: The formula `transform = scaleY(0.6) translate3d(X, Y, 0)` is applied globally. Child elements that require upright z-axis projection receive the exact inverse matrix `transform = matrix(1, 0, 0, 1.666, 0, 0)`.

## 4. "Living World" Volumetrics
- **Volumetric Fog**: Implement an `<feTurbulence>` filter tied to an `<feDisplacementMap>`. We animate the `baseFrequency` property using `requestAnimationFrame` to create fluid, rolling mist over `locked: true` regions.
- **Dynamic Lighting Engine**: A global `LightManager` singleton calculates a faux-sun vector `[sunX, sunY]`. All `<feDropShadow>` elements on mountains and landmarks update their `dx` and `dy` based on the delta between the object's absolute position and the sun vector.

## 5. Phase 5: Ecosystem Integration (The Complete Platform)
**Objective:** Evolve the graphical map into a fully functional, accessible, and persistent learning platform.

- [ ] **State Persistence & Backend Sync**: 
  - Define the `Data Layer` within `control/` to synchronize the `GlobalStore` with a backend API (Node.js/Firebase).
  - Implement async queueing to ensure map terraforming events (e.g., unlocking a region) are persisted securely without blocking the 60fps render loop.
- [ ] **Spatial Audio Engine**:
  - Integrate a context-aware Web Audio API layer.
  - Implement dynamic audio mixing based on camera coordinates (e.g., ambient wind near Highlands, mechanical clanking near Systems Republic, ocean waves at the coastline).
- [ ] **Accessibility (a11y) Overlay**:
  - Generate an invisible, semantic HTML DOM tree perfectly mirrored over the SVG coordinates.
  - Ensure screen readers and keyboard-only users can `Tab` through regions, read lore, and launch challenges without requiring mouse-drag interactions.
- [ ] **Curriculum UI (Mission Control)**:
  - Establish the HTML/CSS protocols for the learning interface.
  - When entering a track, render glassmorphic Skill Trees and Code Editors as `<dialog>` modals that slide over the map, preserving the 2.5D immersion in the background.
- [ ] **Mobile & Touch Topology**:
  - Refactor `CameraPhysics.js` to natively support multi-touch pinch-to-zoom and momentum panning.
  - Implement dynamic scaling for region hitboxes to ensure touch-targets meet standard mobile accessibility metrics (min 44x44px).

## 6. Deployment & Roadmap
- **Phase 1 (Current)**: Implement Context/Control scaffolding, establish `GlobalStore`, and build the Perlin Coastline generator.
- **Phase 2**: Implement A* Pathfinding for rivers/roads and Poisson Disk Sampling for ecology.
- **Phase 3**: Implement SVG ViewBox Culling for infinite performance scaling.
- **Phase 4**: Integrate Gamification (progress unlocks, volumetric fog receding).
- **Phase 5**: Backend Sync, Spatial Audio, Accessibility, and UI Overlays.
